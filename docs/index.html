Certified grid-side behavior for an AI UPS

An AI training campus can step its power by 40 MW in an instant, over and over. A battery and inverter between the campus and the grid can hide that. This is a proof that it does: for every load profile in range, the grid sees a bounded ramp, the feeder voltage never jumps, and the battery never saturates or runs empty.

Exhibit A: the system

Where the UPS sits, and the four parts of the controller
  GRID ---- feeder: 10 km, 69 kV ---- PCC ---+------------------------------- AI CAMPUS
  stiff source                       V(t)   |  Pg = grid power                   PL(t) in [60, 100] MW
                                            |                                    steps allowed
                                 +----------+---------------------------------------------+
                                 | AI UPS        Pb = PL - Pg : the battery covers the gap |
                                 |                                                         |
                                 |   PL --> (+) --> [ low-pass, tau = 180 s ] --> [ clip +/-R ] --> Pg
                                 |           ^                                             |
                                 |           |   s = clip(ke * (eref - w), +/-10 MW)       |
                                 |           +-- [charge loop] <-- w = e + tau(Pg-80)/3600 |
                                 |                                                         |
                                 |   battery e(t):  de/dt = -phi(Pb)/3600,   eta = 0.95    |
                                 +---------------------------------------------------------+

The grid only ever sees Pg. The low-pass smooths the load, the clip caps its slope at R, and the charge loop slowly pulls the battery back toward the middle so the next burst can't drain it. The proof shows the battery limit is never reached, so the grid really does see exactly Pg.

Exhibit E: the proof

32 faces, each closed by branch-and-bound on a thin band just outside it

To show S can't be left, it's enough to show the state points inward on a thin band outside each face, for every load in [60, 100] MW. Branch-and-bound splits that band into boxes until interval arithmetic, rounded outward, proves the direction on every box. If it ever finds a box where it can't, it reports a counterexample instead.

Boxes needed per face (bars) and deepest split. Total 27,230 boxes, max depth 40, 1.4 s. Separate proofs bound the energy window, the grid power range and the battery power.

Frequently asked questions


What does "assumed parameters" mean?
Every number in the model is written in one file with a one-line source. The campus range (60 to 100 MW), the 10 MW/min ramp limit, the 95% efficiency and the feeder (10 km, 69 kV, 0.05 + j0.35 Ω/km) are round values I chose to be plausible for a ~100 MW campus. None come from a real site, a utility tariff or ON.energy. The proof holds for these values exactly, and the code reruns it for any others.


Is this ON.energy's product?
No. It's a public model of the idea behind an AI UPS, with my own controller. No ON.energy hardware, data or controller is used.


Is it a simulation or a proof?
The four claims are proofs: they hold for every load profile in range, not the ones that were simulated. The live exhibits are simulations, shown to make the proof visible.


What doesn't it cover?
Fast inverter dynamics, faults and protection, and the real grid behind the feeder. 16 of 45 designs in the search got no certificate, which is a limit of the search, not proof none exists. The branch-and-bound starts from a padded floating-point polygon, and the code is tested, not formally verified.


What's next?
Fleets of these on one grid: whether many UPS units can be proved to damp oscillations together and ride through line outages, and what a next-generation unit should look like in hardware.
